# Фронтенд «Навык дня»

Адаптивный React + Vite, отдельный Docker-контейнер с Nginx. Интерфейс основан на последних макетах `expressive-reviewed`. Регистрация, вход, письма и управление аккаунтом подключены к настоящему [Auth Service](../auth-service/README.md). Статистика вакансий, roadmap и параметры навыков пока демонстрационные.

## Запуск

Из корня репозитория:

```sh
docker compose up -d --build
```

Сайт: http://127.0.0.1:8080. В локальном Compose подтверждение почты отключено: зарегистрируйтесь и сразу войдите. Пароль — от 12 до 128 символов. Готовых пользовательских паролей и администратора по умолчанию нет. Восстановление пароля и смена email используют письма в Mailpit: http://127.0.0.1:8025; внешняя доставка почты не подключена.

Compose поднимает frontend, api-gateway, auth-service, PostgreSQL, Mailpit и Aspire Dashboard. После изменения исходников повторите запуск с `--build`. Параметры — в [../.env.example](../.env.example). При смене `FRONTEND_PORT` также измените `PUBLIC_ORIGIN`, чтобы ссылки из писем и проверка Origin указывали на правильный адрес.

Журналы запросов и трассировки Gateway → Auth Service: http://127.0.0.1:18888.
В DevTools → Network скопируйте `X-Trace-ID` из ответа API и найдите связанную
трассировку. Пример показа — в [observability/README.md](../observability/README.md).

```sh
docker compose ps
docker compose logs -f frontend
docker compose stop
```

Фронтенд собирается через Node.js 24 и `npm ci`, готовая статика раздаётся Nginx на 8080. `/healthz` — проверка здоровья; хешированные assets кешируются, HTML обновляется без кеша. Шрифт Inter хранится локально вместе с лицензией.

## Авторизация и будущие API

Формы получают настройку подтверждения через `GET /api/auth/config`. При
`AUTH_REQUIRE_CONFIRMED_EMAIL=false` регистрация не отправляет письмо, кнопка
повторного подтверждения скрыта, после регистрации доступен переход ко входу.
Чтобы вернуть подтверждение, установите `AUTH_REQUIRE_CONFIRMED_EMAIL=true`
в `.env` и пересоздайте Auth Service: `docker compose up -d auth-service`.

Все `/api/*` передаются через `API_GATEWAY_URL` в отдельный [API Gateway](../api-gateway/README.md), с сохранением пути. Для `/api/auth/*` шлюз удаляет `/api` и отправляет запрос в Auth Service. Браузерные адреса, cookies и работа с токенами сохранены. `AUTH_SERVICE_URL` во фронтенде больше не используется. Неподключённые API возвращают JSON 404; ошибка API не заменяется HTML приложения. OpenAPI Auth Service: http://127.0.0.1:8080/api/auth/openapi/v1.json.

Access JWT хранится только в памяти, refresh — в HttpOnly-cookie. Сессия восстанавливается при перезагрузке и продлевается автоматически; выход отзывает её на сервере. Пароли и токены не попадают в localStorage. Для серверных запросов используются [src/auth.js](src/auth.js) и [AuthProvider](src/components/AuthProvider.jsx).

План и профиль доступны после входа. Админпанель требует роли Admin, назначенной сервером; её работа с вакансиями пока локальная. Смена почты требует текущего пароля и письма подтверждения на новый адрес. Смена и восстановление пароля отзывают все сессии. Удаление учётки требует пароля и подтверждения.

Демопараметры плана сохраняются отдельно для каждого пользователя в `skill-day-profile:<userId>`. Старый общий ключ `skill-day-profile` автоматически не переносится, чтобы не присвоить чужие данные новому аккаунту. Демопометки администратора — отдельно в `skill-day-admin`.

## Разработка и проверки

Запустите Compose, затем:

```sh
cd frontend
npm ci
npm run dev
```

Vite: http://127.0.0.1:5173. `vite.config.js` перенаправляет `/api/*` в работающий Nginx на 8080, затем запросы проходят через Gateway. Письма по умолчанию ведут на адрес из `PUBLIC_ORIGIN`.

```sh
npm run build
npm test
```

Обычные браузерные тесты проверяют интерфейс с изолированными ответами Auth API, используют установленный Google Chrome и ширины 360, 390, 768, 1024 и 1440 px. API-интеграционные сценарии по умолчанию пропускаются. Для проверки настоящей регистрации, писем и восстановления против Docker:

```sh
AUTH_INTEGRATION=1 PLAYWRIGHT_BASE_URL=http://127.0.0.1:8080 npm run test:e2e -- --grep 'Real auth-service'
```

Для частичного плана отметьте «Анализ требований», «Моделирование данных» и UML. Нулевой экран показывается без навыков; базовые навыки остаются в рекомендациях до отметки «изучен». Для состояния «слоёв нет» оставьте только Владивосток: в демонстрационном срезе вакансий там нет. Пересчёт выполняется в Web Worker с отображением состояния обработки.

Вакансии-основания — только те, которые становятся доступными при добавлении навыка в контексте выбранного шага; их число равно вкладу. При открытии карточки контекст прогноза фиксируется, а отметки изучения показывают фактические навыки пользователя. В карточке навыка один список вакансий-оснований, охват до и после, обязательные навыки и фактически изученные отметки. Работодатель, условия и дословные требования убраны. В синтетических данных нет внешних ссылок; HTTP(S)-ссылка показывается, если предоставлена в данных. Материалы обучения без ресурсов не показаны.

## Демонстрационная аналитика

[src/data.js](src/data.js) содержит по 120 синтетических вакансий на направление: 90 Москва и 30 удалённых. Уровень выбирается на лендинге, в публичной статистике, профиле и плане. Демоданные содержат стажёра, Junior, Middle и Senior; выбор «Все уровни» сохраняет полный срез. Выбранные регионы соединяются условием «ИЛИ», пустой выбор означает всю Россию. Срез — 20.10.2026, демонстрационная история с шагом пять дней. Согласованный интервал обновления — **5 дней**; реальное расписание будет в backend-сервисах сбора и аналитики.

Охват — число вакансий, все обязательные навыки которых изучены. Вклад навыка — увеличение этого числа; прирост охвата — изменение доли в процентных пунктах. Слои вычисляются динамически по числу недостающих обязательных навыков, без ограничения четырьмя. Выбор слоя отбирает его вакансии и заново рассчитывает весь план, охват, вклад и основания по этому набору. Граф и таблица используют один результат; переключение таба сохраняет фильтр. Для примера слой 3 содержит 46 вакансий, вклады шагов — 24 / 14 / 8.

Базовые навыки идут сверху. Прогноз специализированных шагов учитывает все основы, затем предыдущие шаги; контекст совпадает в графе, таблице и карточке навыка. Число шагов не ограничено тремя; проверен план на двадцать навыков. На шаге до пяти совместно нужных навыков, выбираются ближайший непустой слой и наибольший прирост. Для большого набора возможен частичный шаг, уменьшающий дефицит при нулевом приросте. Этот демонстрационный алгоритм заменит Recommendation Service.

Пример: текущий охват 24/120 (20%), после основ 72/120 (60%); далее Git +24, BPMN +16, SOAP +8. Навыки и профиль ещё не сохраняются на сервере — это следующая интеграция.

## Палитра

| Назначение            | Цвет      |
| --------------------- | --------- |
| Действия              | `#2F54EB` |
| Текст и тёмные секции | `#172245` |
| Фон                   | `#F1F4FC` |
| Карточки              | `#FFFFFF` |

Подписи кнопок центрированы, данные выровнены слева. На узлах графа только названия; вклад, прирост охвата с объяснением процентных пунктов и число оснований показаны в подсказке по наведению или фокусу. На телефоне первый тап открывает подсказку, повторный — карточку навыка. Узлы расположены компактной змейкой со стрелками, большая карта ограничена по высоте; мобильная таблица превращается в карточки. Статусы и классы различаются по тексту и форме, предусмотрена печать. Исходники Figma исключены из Git и не нужны для работы сайта.
