# Фронтенд «Навык дня»

React + Vite, отдельный Docker-сервис с Nginx. Интерфейс перенесён из последних согласованных ярких макетов `expressive-reviewed`. API пока нет: страницы работают на локальных демонстрационных данных, а Nginx подготовлен для будущего API Gateway.

## Запуск в Docker

Из корня репозитория:

```sh
docker compose up -d --build frontend
```

Откройте **http://127.0.0.1:8080**. Нужен запущенный Docker Desktop или Docker Engine с Compose. При изменении исходников повторите команду с `--build`.

```sh
docker compose ps
docker compose logs -f frontend
docker compose stop frontend
```

Образ собирается в два этапа: Node.js 24 устанавливает зависимости через `npm ci` и собирает приложение; итоговый образ Nginx содержит только готовую статику. Node.js и dev-сервер в работающем контейнере не нужны. `/healthz` возвращает `200 ok`; healthcheck включён в образ. Отсутствие Gateway не препятствует запуску.

Параметры приведены в [../.env.example](../.env.example). При необходимости скопируйте его в `.env` в корне репозитория. По умолчанию порт доступен только на локальном компьютере. Для другого порта:

```sh
FRONTEND_PORT=8081 docker compose up -d frontend
```

## Подключение будущего API

Браузер будет обращаться к `/api` на том же домене. В контейнере `API_GATEWAY_URL` задаёт внутренний адрес Gateway, по умолчанию `http://api-gateway:8080`. Подключите Gateway к общей Docker-сети с фронтендом или укажите доступный из контейнера адрес. URL должен содержать протокол, хост и порт, без пути и завершающего `/`.

Nginx снимает префикс `/api`: `/api/profile?x=1` передаётся как `/profile?x=1`. Заголовок Authorization и тело запроса передаются стандартным proxy-модулем. Переменная применяется при старте контейнера; после её изменения выполните `docker compose up -d frontend`. Если Gateway отсутствует, API-запрос получает `502`, а не HTML приложения. Статика и `/healthz` продолжают работать. TLS для внешнего домена можно завершать на входном reverse proxy.

Договорённого OpenAPI ещё нет, поэтому формы и расчёты не отправляют запросы на предполагаемые серверные методы. Точка демонстрационных данных и вычислений — [src/data.js](src/data.js); после появления API её нужно заменить серверным провайдером. Реальные авторизация, роли администратора, серверное хранение, сбор вакансий и обновление срезов подключаются отдельно. В этой версии показан согласованный интервал обновления **5 дней**; браузер не запускает сбор данных по расписанию.

## Локальная разработка

```sh
cd frontend
npm ci
npm run dev
```

Vite: http://127.0.0.1:5173. Для будущего `/api` используется конфигурация контейнера; dev-сервер пока обслуживает только интерфейс.

```sh
npm run build
npm run preview
npm test
```

`npm test` запускает модульные проверки расчётов и браузерные сценарии Playwright. Используется установленный Google Chrome. При его отсутствии измените `channel` в [playwright.config.js](playwright.config.js) и установите браузер Playwright. Браузерные проверки охватывают ширины 360, 390, 768, 1024 и 1440 px.

Те же браузерные сценарии можно запустить против уже работающего контейнера, без Vite:

```sh
PLAYWRIGHT_BASE_URL=http://127.0.0.1:8080 npm run test:e2e
```

## Страницы и состояния

| Адрес | Страница |
| --- | --- |
| `#/` | Лендинг, пример графического roadmap, дата среза и три направления по пять навыков |
| `#/market` | Публичная статистика: направление и регион, классификация требований, поиск и тренды |
| `#/login`, `#/register`, `#/reset` | Вход, регистрация, восстановление; валидация без отправки паролей |
| `#/plan` | Нулевой экран, графический roadmap по умолчанию, переключение на таблицу, слои дефицита и пересчёт |
| `#/profile` | Направление, регионы, отдельно базовые и специализированные навыки, настройки аккаунта |
| `#/admin` | Накопитель необработанного, три действия над записью, две пометки вакансии, доля нераспознанных структур |

Карточка навыка открывается из плана: охват до и после, один список вакансий-оснований и обязательные навыки с отметками фактически изученных. Работодатель, условия и цитаты требований в пользовательской карточке отсутствуют. Внешних ссылок в синтетическом наборе нет; при наличии корректного HTTP(S)-адреса в данных карточка показывает ссылку. Материалы обучения не показаны, поскольку ресурсы не предоставлены.

Все состояния получаются действиями пользователя; служебных переключателей макетов на страницах нет. В новом браузере начните с `#/plan` и отметьте навыки или заполните профиль. Чтобы увидеть частичный план из макетов, отметьте «Анализ требований», «Моделирование данных» и UML. Для состояния «слоёв нет» оставьте в профиле только Владивосток: в демонстрационном наборе вакансий там нет. Кнопка пересчёта выполняет расчёт в Web Worker и блокирует изменение результата на время обработки.

## Данные и расчёты

По 120 синтетических вакансий в каждом из трёх направлений. Москва и удалённая работа составляют 90 и 30 вакансий; несколько регионов соединяются условием «ИЛИ», пустой выбор означает всю Россию. Текущий демонстрационный срез — 20.10.2026, график содержит демонстрационную историю с шагом в пять дней.

Охват — число вакансий, все обязательные навыки которых изучены. Вклад навыка — изменение этого числа; прирост охвата выражен в процентных пунктах. Слои строятся динамически по числу недостающих обязательных навыков, без ограничения четырьмя слоями.

Базовые навыки показываются до отметки «изучен». В прогнозе специализированных шагов сначала учитываются все базовые навыки, затем предыдущие шаги — этот контекст подписан в интерфейсе и совпадает с карточкой выбранного навыка. План строит до трёх шагов из ближайшего непустого слоя, выбирая набор с наибольшим приростом охвата; в шаге до пяти навыков. Для большого набора возможен частичный шаг с нулевым приростом и уменьшением дефицита. Алгоритм является демонстрационным и будет заменён Recommendation Service.

Пример частичного профиля: текущий охват 24/120 (20%); SQL отдельно добавляет 18 вакансий; после основ охват 72/120 (60%). Далее Git добавляет 24 вакансии, BPMN — 16, SOAP — 8. В таблице и графическом плане показатели совпадают.

Навыки, email и фильтры хранятся в `localStorage` (`skill-day-profile`); действия администратора — отдельно (`skill-day-admin`). Пароли не сохраняются и не отправляются. Формы не имитируют успешную серверную авторизацию. Удаление аккаунта с подтверждением очищает локальный профиль; административные демонстрационные пометки остаются отдельно. Флаги и обработка терминов в админпанели сохраняют локальный результат проверки; они не изменяют данные рекомендаций и не реализуют серверную нормализацию.

## Визуальное решение

| Назначение | Цвет |
| --- | --- |
| Основной, действия | `#2F54EB` |
| Текст, тёмные секции | `#172245` |
| Фон страницы | `#F1F4FC` |
| Карточки, текст на тёмном фоне | `#FFFFFF` |

Шрифт Inter хранится в `public/fonts` вместе с лицензией OFL, внешние шрифтовые сервисы не нужны. Графический план состоит из интерактивных карточек со стрелками. Названия навыков и данные выровнены слева, подписи кнопок — по центру. Интерфейс адаптивный от 360 px; мобильная таблица превращается в карточки. Классы требований, порядок шагов и статусы различимы по тексту и форме, предусмотрены стили печати.

Исходники макетов и материалы импорта в Figma остаются локальными и исключены из Git. Для запуска сайта они не требуются.
