# Фронтенд «Навык дня»

Адаптивный React + Vite, отдельный Docker-контейнер с Nginx. Интерфейс основан на последних макетах `expressive-reviewed`. Регистрация, вход, письма и управление аккаунтом подключены к настоящему [Auth Service](../auth-service/README.md). Статистика вакансий, roadmap и параметры навыков пока демонстрационные.

## Запуск

Из корня репозитория:

```sh
docker compose up -d --build
```

Сайт: http://127.0.0.1:8080. Письма подтверждения и восстановления доступны локально в Mailpit: http://127.0.0.1:8025; внешняя доставка почты не подключена. Сначала зарегистрируйтесь, подтвердите почту по ссылке из письма, затем войдите. Пароль — от 12 до 128 символов. Готовых пользовательских паролей и администратора по умолчанию нет.

Compose поднимает frontend, auth-service, PostgreSQL и Mailpit. После изменения исходников повторите запуск с `--build`. Параметры — в [../.env.example](../.env.example). При смене `FRONTEND_PORT` также измените `PUBLIC_ORIGIN`, чтобы ссылки из писем и проверка Origin указывали на правильный адрес.

```sh
docker compose ps
docker compose logs -f frontend
docker compose stop
```

Фронтенд собирается через Node.js 24 и `npm ci`, готовая статика раздаётся Nginx на 8080. `/healthz` — проверка здоровья; хешированные assets кешируются, HTML обновляется без кеша. Шрифт Inter хранится локально вместе с лицензией.

## Авторизация и будущие API

`/api/auth/*` проксируется напрямую в Auth Service с удалением префикса `/api`. `AUTH_SERVICE_URL` задаётся при старте контейнера. Остальные `/api/*` направляются в будущий Gateway через `API_GATEWAY_URL`. Ошибка API не заменяется HTML приложения. OpenAPI Auth Service: http://127.0.0.1:8080/api/auth/openapi/v1.json.

Access JWT хранится только в памяти, refresh — в HttpOnly-cookie. Сессия восстанавливается при перезагрузке и продлевается автоматически; выход отзывает её на сервере. Пароли и токены не попадают в localStorage. Для серверных запросов используются [src/auth.js](src/auth.js) и [AuthProvider](src/components/AuthProvider.jsx).

План и профиль доступны после входа. Админпанель требует роли Admin, назначенной сервером; её работа с вакансиями пока локальная. Смена почты требует текущего пароля и письма подтверждения на новый адрес. Смена и восстановление пароля отзывают все сессии. Удаление учётки требует пароля и подтверждения.

Демопараметры плана сохраняются отдельно для каждого пользователя в `skill-day-profile:<userId>`. Старый общий ключ `skill-day-profile` автоматически не переносится, чтобы не присвоить чужие данные новому аккаунту. Демопометки администратора — отдельно в `skill-day-admin`.

## Разработка и проверки

Запустите Compose, затем:

```sh
cd frontend
npm ci
npm run dev
```

Vite: http://127.0.0.1:5173. `vite.config.js` перенаправляет auth-запросы в работающий Nginx на 8080, который передаёт их сервису. Письма по умолчанию ведут на адрес из `PUBLIC_ORIGIN`.

```sh
npm run build
npm test
```

Обычные браузерные тесты проверяют интерфейс с изолированными ответами Auth API, используют установленный Google Chrome и ширины 360, 390, 768, 1024 и 1440 px. API-интеграционные сценарии по умолчанию пропускаются. Для проверки настоящей регистрации, писем и восстановления против Docker:

```sh
AUTH_INTEGRATION=1 PLAYWRIGHT_BASE_URL=http://127.0.0.1:8080 npm run test:e2e -- --grep 'Real auth-service'
```

Для частичного плана отметьте «Анализ требований», «Моделирование данных» и UML. Нулевой экран показывается без навыков; базовые навыки остаются в рекомендациях до отметки «изучен». Для состояния «слоёв нет» оставьте только Владивосток: в демонстрационном срезе вакансий там нет. Пересчёт выполняется в Web Worker с отображением состояния обработки.

В карточке навыка один список вакансий-оснований, охват до и после, обязательные навыки и фактически изученные отметки. Работодатель, условия и дословные требования убраны. В синтетических данных нет внешних ссылок; HTTP(S)-ссылка показывается, если предоставлена в данных. Материалы обучения без ресурсов не показаны.

## Демонстрационная аналитика

[src/data.js](src/data.js) содержит по 120 синтетических вакансий на направление: 90 Москва и 30 удалённых. Выбранные регионы соединяются условием «ИЛИ», пустой выбор означает всю Россию. Срез — 20.10.2026, демонстрационная история с шагом пять дней. Согласованный интервал обновления — **5 дней**; реальное расписание будет в backend-сервисах сбора и аналитики.

Охват — число вакансий, все обязательные навыки которых изучены. Вклад навыка — увеличение этого числа; прирост охвата — изменение доли в процентных пунктах. Слои вычисляются динамически по числу недостающих обязательных навыков, без ограничения четырьмя.

Базовые навыки идут сверху. Прогноз специализированных шагов учитывает все основы, затем предыдущие шаги; контекст совпадает в графе, таблице и карточке навыка. До трёх шагов, до пяти навыков на шаг, ближайший непустой слой и наибольший прирост. Для большого набора возможен частичный шаг, уменьшающий дефицит при нулевом приросте. Этот демонстрационный алгоритм заменит Recommendation Service.

Пример: текущий охват 24/120 (20%), после основ 72/120 (60%); далее Git +24, BPMN +16, SOAP +8. Навыки и профиль ещё не сохраняются на сервере — это следующая интеграция.
